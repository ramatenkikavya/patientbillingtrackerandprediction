Model & target definition
Target: Underpaid bill (1 when AmountPaid is less than TotalBillAmount).

Training: Positive, non-missing bill rows only. 80/20 stratified holdout.

Features: Total bill amount, department, payment type, bill month and year.

Important: The dataset does not contain an explicit target column, so this is a derived operational prediction task—not a claim of clinical or financial causality.

About this dashboard

This dashboard is generated from the supplied patient billing dataset. It is designed as a Power BI-style single-page application that runs entirely in the browser.

Data quality is visible rather than hidden: the source contains missing departments, missing bill dates, missing bill amounts, duplicate rows/Bill IDs, negative payment values and bills where payment exceeds the bill. Dashboard financial KPIs use positive, numeric bill amounts; model training excludes missing/non-positive bill amounts.

Prediction limitation: there is no explicit outcome/target column in the source data. The prediction module therefore uses a clearly labeled derived target: underpayment. This should be treated as an operational demonstration, not as a validated production revenue-cycle model.

Deployment: save/upload this single index.html to GitHub Pages. Chart.js and SheetJS are loaded from public CDNs; no Python, backend, database, build step or npm installation is required.
